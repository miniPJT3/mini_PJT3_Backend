# 기획서

# 📑 보안 격리 기반 일회용 가상 계좌 결제 시스템

## 1. 프로젝트 개요

- **배경**: 커머스 결제 시 고객의 민감 정보 유출을 원천 차단하고, 금융권 수준의 네트워크 격리를 통해 해킹 시도를 무력화하는 안전한 결제 시스템 구축.
- **핵심 가치**: 데이터 휘발성(Volatility), 네트워크 격리(Isolation), 결제 정합성(Consistency).

---

## 2. 주요 기능 및 비즈니스 로직

### [Service A] 가상 계좌 발급 및 생명주기 관리

- **기능**: 주문 발생 시 1:1 매칭되는 랜덤 가상 계좌 발급.
- **유효 시간**: 발급 시점으로부터 **3시간**. (만료 시 자동 취소)
- **보안 로직**:
    - **분산 락(Redis)**: 동일 주문에 대한 중복 발급 요청 차단.
    - **데이터 파기**: 결제 완료 즉시 계좌번호 마스킹 및 Soft Delete 처리.
    - **로그 보안**: 로그 파일 내 계좌번호 패턴 자동 마스킹(Logback Masking).

### [Service B] 입금 승인 및 결제 정합성 검증

- **기능**: 외부 은행(Mock API) 신호를 수신하여 결제 완료 처리.
- **보안 로직**:
    - **멱등성 설계**: 동일 트랜잭션 ID에 대해 단 1회만 결제 승인.
    - **Webhook 보안**: API Key 및 인가된 IP(화이트리스트) 검증.
    - **입금 시뮬레이터**: 성공/실패/위변조 시나리오를 테스트할 수 있는 관리 도구 제공.

### [Service C] 판매자 관제 및 매출 관리

- **기능**: 판매자용 매출 통계 및 실시간 보안 로그 모니터링.
- **보안 로직**:
    - **침입 탐지**: 비정상적인 입금 시도(Rate Limiting 위반 등) IP 탐지 및 알림.
    - **접근 제어**: RBAC(Role Based Access Control) 기반의 관리자 전용 페이지 보호.

---

## 3. 시스템 아키텍처 및 보안 시나리오 (Infra)

- **망 분리**: 결제 핵심 서버를 **Private Subnet**에 배치하여 외부 인터넷 직접 접속 차단.
- **통로 단일화**: 모든 트래픽은 **API Gateway → Load Balancer**를 거친 인가된 요청만 허용.
- **민감 정보 관리**: DB 패스워드, API Key 등은 **AWS Secrets Manager**를 통해 런타임에만 주입.
- **단방향 통신**: 서버는 **NAT Gateway**를 통해 외부 은행 API로 아웃바운드 통신만 허용.
